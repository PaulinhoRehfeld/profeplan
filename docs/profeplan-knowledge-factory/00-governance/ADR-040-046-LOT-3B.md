# ADRs propostas — Lote 3B

Data: 7 de agosto de 2026.

## Status geral

**Propostas — aguardando aprovação humana.**

Complementam ADR-033 a ADR-039 e não as substituem.

## ADR-040 — Adapters Supabase recebem client por injeção

**Status:** proposto

`@profeplan/knowledge-factory-supabase` será o pacote concreto.

O pacote não lê `process.env`, não cria credenciais, não importa `api/_lib/supabaseAdmin.ts` e não conhece project ref de produção.

Clients Supabase são construídos na composition root e injetados.

`@supabase/supabase-js` será dependência explícita do pacote quando o primeiro PR for autorizado.

## ADR-041 — Contextos SYSTEM e REQUESTER são separados

**Status:** proposto

- SYSTEM: client server-side privilegiado para corpus global/auditoria;
- REQUESTER: client autenticado sob identidade do usuário para operações privadas sujeitas a RLS, especialmente OPP.

`service_role` não será o padrão para simular professor.

## ADR-042 — Escritas multi-tabela não usarão pseudo-transações

**Status:** proposto

Chamadas Supabase independentes não serão tratadas como uma transação.

Operações indivisíveis, como componente + versão e OPP + evento, ficam bloqueadas até função PostgreSQL/RPC transacional ou fronteira atômica equivalente, versionada/testada/aprovada.

Não criar Unit of Work genérico fictício.

## ADR-043 — Erros Supabase/PostgreSQL são traduzidos no adapter

**Status:** proposto

Códigos provider serão convertidos para erros estáveis e sanitizados.

Taxonomia inicial:

- `NOT_FOUND`;
- `CONFLICT`;
- `CONSTRAINT_VIOLATION`;
- `UNAUTHORIZED`;
- `FORBIDDEN`;
- `UNAVAILABLE`;
- `INVALID_RESPONSE`;
- `UNKNOWN`.

SQLSTATE, query e detalhes internos não atravessam para domínio/API/UX.

## ADR-044 — Observabilidade de persistência é injetada

**Status:** proposto

Adapters não dependerão diretamente de `@profeplan/logger` no primeiro PR.

Receberão interface mínima de telemetria estruturada.

Logs poderão conter operação, duração, aggregate/correlation, outcome e erro estável, mas nunca secrets ou conteúdo pedagógico bruto.

## ADR-045 — Primeiro PR 3B implementa somente AuditRepository

**Status:** proposto

A primeira fatia será:

`AuditRepository ↔ public.kf_audit_events`

Motivos:

- uma tabela;
- porta completa;
- append-only;
- sem transação multi-tabela;
- sem mudança de contrato;
- prova client injection, mapper, erros, observabilidade e Supabase descartável.

Nenhuma segunda porta entra no mesmo PR.

## ADR-046 — Lookup de currículo ativo deve incluir etapa

**Status:** proposto

A porta atual `findActivePackageByState(state)` é incompatível com o schema, que permite pacote ativo por `(state, stage)`.

Antes do adapter curricular será necessária alteração equivalente a:

`findActivePackage(state, stage)`

Nenhuma alteração na porta é autorizada por este documento.
